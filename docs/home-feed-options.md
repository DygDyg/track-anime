# Главная: варианты ленты по shikimoriId

Документ для принятия решения. Статус: **гибрид B + релизы** (2026-06-24).

Дата фиксации контекста: 2026-06-22.

---

## Текущее состояние

### Как работает сейчас (гибрид)

- **Фаза 1 — «Новые серии»:** тайтлы из `KodikEpisodeRelease`, одна карточка на `shikimoriId`, последняя серия среди всех озвучек, сортировка по `releasedAt`.
- **Фаза 2 — «Каталог»:** остальные тайтлы с сериями из `KodikMaterial`, группировка по `shikimoriId`, сортировка по `kodikUpdatedAt`. Тайтлы из фазы 1 **не дублируются**.
- Пагинация: курсор `{ phase: 'releases' | 'catalog', releasedAt, id }`.
- Код: `src/lib/releases.ts` → `queryFreshReleasesPerTitle()` + `queryCatalogReleasesPerTitle()`.

### Цифры на проде (2026-06-22)

| Метрика | Значение |
|---------|----------|
| Уникальных `shikimoriId` в `KodikMaterial` | **6 375** |
| С загруженными сериями | 6 208 |
| Строк в `KodikEpisodeRelease` | 382 |
| Уникальных тайтлов в релизах | ~124 |
| Тайтлов в ленте главной (текущий SQL) | ~56 |
| Материалов Kodik | 25 768 |
| Серий | ~393 000 |

### Почему мало тайтлов на главной

1. **Мало релизов** — `KodikEpisodeRelease` заполняется только при *новой* серии в `trackLatestRelease()` (`src/db/save-material.ts`). При массовом импорте каталога, если `lastEpisode` уже был известен, релиз часто не создаётся.

2. **Релиз только у «лучшей» озвучки** — SQL выбирает material с макс. `kodikUpdatedAt`, затем ищет релиз именно у него. Если релиз есть у другой озвучки того же `shikimoriId`, тайтл всё равно не показывается.

## Варианты решения

### Вариант A — Backfill `KodikEpisodeRelease`

**Суть:** одноразово (и по cron при необходимости) создать записи релизов для всех материалов, у которых есть `lastSeason` / `lastEpisode`.

**Что менять:**
- Скрипт или admin-action: обход `KodikMaterial` → `upsert` в `KodikEpisodeRelease`.
- Опционально: поправить `trackLatestRelease()`, чтобы при первой загрузке серий тоже создавался релиз.

**Плюсы:**
- Минимальные изменения в SQL ленты.
- Таблица релизов остаётся источником «что вышло недавно».
- Календарь и поиск, завязанные на `KodikEpisodeRelease`, тоже выиграют.

**Минусы:**
- Не решает проблему «релиз у другой озвучки, best material без релиза» без доп. правки JOIN.
- ~25k материалов → много строк в `KodikEpisodeRelease` (по одной на material × последняя серия).
- Лента всё ещё ограничена логикой best material + release на нём.

**Ожидаемый эффект:** существенный рост, но не обязательно до 6k+ тайтлов без доработки JOIN.

**Сложность:** низкая–средняя.

---

### Вариант B — Новый SQL: последняя серия по `shikimoriId` из каталога

**Суть:** переписать `queryLatestReleasesPerTitle()`: группировка по `shikimoriId`, последняя серия из `KodikMaterial` + `KodikEpisode` (или `lastSeason` / `lastEpisode`), **без** обязательного `KodikEpisodeRelease`.

**Что менять:**
- `src/lib/releases.ts` — новый SQL / Prisma-запрос.
- `countLatestReleasesPerTitle()` — синхронно.
- Возможно: `src/lib/calendar.ts`, если нужна та же семантика.

**Плюсы:**
- Главная покажет все тайтлы с сериями (~6 200+ по `shikimoriId`).
- Не зависит от backfill и sync-истории.
- Одна карточка = одно аниме на Shikimori — логично для пользователя.

**Минусы:**
- «Новизна» = `kodikUpdatedAt` / `firstSeenAt`, а не момент появления серии на сайте.
- В ленте могут быть старые тайтлы, просто недавно обновлённые в Kodik.
- `KodikEpisodeRelease` теряет роль фильтра; нужно решить, зачем она дальше (только «новые серии за 24ч»?).

**Ожидаемый эффект:** ~6 200 тайтлов в ленте (с `shikimoriId` и сериями).

**Сложность:** средняя.

---

### Вариант C — Компромисс: группировка по `shikimoriId`, релиз из любой озвучки

**Суть:** оставить `KodikEpisodeRelease`, но при выборе карточки искать последний релиз **среди всех materials с тем же `shikimoriId`**, а не только у best material.

**Что менять:**
- SQL в `src/lib/releases.ts`: `best_release` джойнить по `shikimoriId`, а не `materialId = best_material.kodikId`.
- Backfill (вариант A) желателен, чтобы релизов было больше.

**Плюсы:**
- Сохраняется смысл «лента релизов».
- Исправляет баг с разными озвучками.
- Меньше кардинальных изменений, чем вариант B.

**Минусы:**
- Без backfill по-прежнему мало тайтлов (~124 уникальных в релизах).
- Две озвучки одного тайтла — одна карточка, но какую озвучку показывать нужно явно выбрать (приоритет по дате релиза / озвучке).

**Ожидаемый эффект:** до ~124+ тайтлов сразу; с backfill — значительно больше, но всё ещё «только то, что есть в релизах».

**Сложность:** низкая–средняя.

## Рекомендация (для обсуждения)

| Цель | Вариант |
|------|---------|
| «Видеть все аниме с сериями на главной» | **B** |
| «Лента именно новых серий, как сейч задумано» | **A + C** |
| Быстрый win без переписывания SQL | **A** или **C** |

Комбинация **B + отдельный блок «Новые серии»** (из `KodikEpisodeRelease`) — самый гибкий UX, но больше работы.
