# Проверка проекта с AI-ассистентом

Инструкция для Track Anime: как искать ошибки с Codex, Cursor или локальной моделью, не полагаясь на широкий запрос «проверь весь проект».

## Важно знать

В проекте **нет автоматических unit-тестов** (`*.test.ts` / `*.spec.ts`, команды `npm test` в `package.json` нет).

Проверка строится из:

1. **команд терминала** (TypeScript, сборка);
2. **узких запросов к модели** (Codex analysis / Cursor Ask / Debug mode);
3. **ручного прогона** в браузере;
4. **debug-скриптов** для конкретных подсистем.

---

## Что такое «тесты» в этом проекте

| Что | Что делает | Когда запускать |
|-----|------------|-----------------|
| `npx tsc --noEmit` | Проверяет TypeScript (типы, импорты) | Перед каждой проверкой |
| `npm run build` | Полная сборка Next.js — ловит ошибки в страницах и API | Перед коммитом / деплоем |
| `npm run lint` | ESLint | Когда lint настроен и работает |
| Debug-скрипты | Проверяют конкретную логику через БД | Подозрение на конкретную фичу |
| Ручная проверка в браузере | Логин, плеер, списки, поиск | После изменений в UI |

Debug-скрипты (см. также `AI_CONTEXT.md`):

```bash
node scripts/debug-user-rates.mjs
node scripts/debug-history-new.mjs
tsx scripts/check-poster.ts <shikimoriId>
```

## Режимы Codex и Cursor

### Codex

- Подходит для чтения файлов, запуска команд, исправления кода и проверки результата.
- Для аудита без правок прямо формулируйте ограничение: «только анализ, код не менять».
- Для исправлений задавайте один конкретный баг или небольшую фичу, затем требуйте проверку (`npx tsc --noEmit`, `npm run build` по необходимости).
- Codex должен читать `AGENTS.md`, `AI_RULES.md`, `AI_CONTEXT.md` и реальные файлы по теме.

### Cursor Ask mode

- Модель **только отвечает**, не меняет файлы.
- Лучший режим для локальной модели: **анализ узкой области**.
- Прикрепляйте 1–5 файлов через `@`.

### Cursor Debug mode

- Не «проверка всего проекта», а **один конкретный баг**.
- Описываете: *что делали → что ожидали → что получили*.
- Модель ищет цепочку вызовов и причину.
- Нужен **воспроизводимый сценарий** (URL, кнопка, ошибка в консоли/терминале).

### Cursor Agent mode

- Модель **сама читает файлы, запускает команды, правит код**.
- На **большом проекте** локальная модель часто «угадывает» пути и функции, которых нет.
- **Не используйте** для «проверь весь проект на ошибки».

**Правило:** один чат/задача = одна тема. «Проверить весь проект» = терминал + узкий анализ по модулям. Исправление = один подтверждённый баг или ограниченная задача.

## Протокол проверки (без галлюцинаций)

### Шаг 0 — автоматика (без AI)

В терминале в корне проекта:

```powershell
cd E:\GitHub\ta_new
npx tsc --noEmit
npm run build
```

- Если есть ошибки — передайте вывод команды ассистенту вместе с конкретным файлом/модулем.
- Если всё зелёное — compile-ошибок нет; дальше смотрите логику и runtime.

### Шаг 1 — одна тема, не «всё»

Из `AI_CONTEXT.md`:

| Тема | Стартовые файлы |
|------|-----------------|
| Auth | `src/lib/auth/shikimori-oauth.ts`, `src/app/api/auth/callback/shikimori/route.ts` |
| Плеер | `src/components/anime/KodikPlayer.tsx`, `src/lib/kodik-player-api.ts` |
| Главная | `src/lib/releases.ts`, `src/components/ReleaseFeed.tsx` |
| История | `src/components/history/HistoryWatchCard.tsx`, `src/lib/history-watch-card.ts` |
| Списки | `src/lib/favorites-sync.ts`, `src/lib/shikimori/user-list-mutations.ts` |
| Поиск | `src/lib/search.ts` |
| Обложки | `src/lib/poster.ts`, `src/app/api/cover/route.ts` |
| Импорт/sync | `src/lib/admin/kodik-sync.ts`, `scripts/kodik-import-full.ts` |

**Один чат = одна тема = 1–5 файлов.**

### Шаг 2 — режим и базовый промпт

**Для анализа без правок:** Codex с явным запретом на изменения или Cursor Ask mode.

**Для исправления одной ошибки:** Codex или Cursor Agent mode с жёстким ограничением scope.

В начале каждого промпта:

```
Правила:
- Не выдумывай файлы и функции
- Если файла нет — пиши ФАЙЛ НЕ НАЙДЕН
- Если не уверен — НЕ ПОДТВЕРЖДЕНО
- Работай только с прикреплёнными файлами и результатами команд
- Ответ: кратко, с цитатами кода (путь + строки)
```

(См. также `AGENTS.md`, `.cursorrules` и `AI_RULES.md` → Local Model Behavior Rules.)

### Шаг 3 — контекст через `@`

Пример для auth:

```
@AI_CONTEXT.md
@src/lib/auth/shikimori-oauth.ts
@src/app/api/auth/callback/shikimori/route.ts

Проверь только OAuth callback: возможные ошибки, race conditions,
несоответствие redirect URI. Не трогай другие модули.
```

### Шаг 4 — требуйте доказательства

Добавляйте в конец промпта:

```
Перед выводами:
1. Перечисли прочитанные файлы
2. Для каждой проблемы — цитата из кода (файл:строка)
3. Если не видел код — пометь НЕ ПОДТВЕРЖДЕНО
4. Не предлагай рефакторинг — только баги и риски
```

### Шаг 5 — проверка ответа модели (вручную)

Для каждого «найденного бага»:

1. Откройте указанный файл — **есть ли эта строка?**
2. Если модель назвала файл, которого нет — **галлюцинация, игнорируйте**.
3. Если баг правдоподобен — только тогда запускайте исправление с задачей «исправь только это».

### Шаг 6 — runtime (браузер)

Мини-чеклист после сборки:

- [ ] `http://localhost:3000` — главная, лента (при пустой ленте: `npm run kodik:sync`)
- [ ] Логин через Shikimori
- [ ] Страница аниме `/anime/<id>` — плеер, прогресс
- [ ] Избранное / списки
- [ ] Поиск

Ошибки из DevTools (F12 → Console / Network) — в отдельный debug-запрос с `@` нужного компонента или с явными путями для Codex.

## Готовые промпты

### A. После `tsc` / `build` (analysis / Ask mode)

```
@AI_CONTEXT.md

Результат команд:
<вставьте вывод tsc или build, если были ошибки>

Разбери только эти ошибки. Для каждой:
- причина
- файл и строка (цитата)
- минимальный fix

Не выдумывай файлы. Нет данных — НЕДОСТАТОЧНО ДАННЫХ.
```

### B. Один модуль (analysis / Ask mode)

```
@AI_CONTEXT.md
@src/lib/favorites-sync.ts
@src/lib/shikimori/user-list-mutations.ts

Проверь sync списков Shikimori ↔ локальная БД.
Ищи: потеря данных, race conditions, несоответствие политике rewatch из AI_CONTEXT.md.

Формат ответа:
| Проблема | Файл:строка | Серьёзность | Fix |
```

### C. Один баг (Debug mode)

```
@src/components/anime/KodikPlayer.tsx
@src/lib/kodik-player-api.ts

Шаги:
1. Открыл /anime/5114
2. Выбрал озвучку X
3. Нажал play

Ожидал: воспроизведение с сохранённой позиции
Получил: <опишите>

Console: <текст ошибки>
Network: <какой запрос упал, status code>

Найди root cause по call chain. Не предлагай правки вне этих двух файлов без пометки НЕ ПОДТВЕРЖДЕНО.
```

### D. Исправление (Codex / Agent mode)

```
Исправь только ошибку в src/lib/search.ts строка ~120:
<описание>. Минимальный diff. Не рефактори.
Не трогай другие файлы. После правки запусти npx tsc --noEmit.
```

## Почему локальная модель «выдумывает» в широком Agent mode

| Причина | Что делать |
|---------|------------|
| Контекст слишком большой | Одна тема, 1–5 файлов через `@` |
| Agent сам «ищет» по всему репо | Узкий запрос + явные пути из `AI_CONTEXT.md` |
| Нет проверки фактов | Требуйте цитаты `файл:строка` |
| Модель даёт общие советы | Блок правил из `AI_RULES.md` |
| Задача размытая | Конкретный сценарий или вывод `tsc`/`build` |

**Золотое правило:** сначала **терминал** (`tsc` + `build`), потом узкий анализ по модулю, затем исправление только для подтверждённого fix.

## Рекомендуемый порядок

1. `npx tsc --noEmit`
2. `npm run build`
3. 6 узких запросов по чеклисту модулей выше
4. Ручной прогон в браузере
5. Debug-запрос — только для конкретного бага

---

## Чего не делать

- «Проверь весь проект на ошибки» широким Agent-запросом
- Доверять списку багов без проверки файлов
- Путать debug-запрос с общим аудитом
- Ждать unit-тестов — их в проекте пока нет
