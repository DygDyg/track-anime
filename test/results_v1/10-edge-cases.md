# Раздел 10 — Edge Cases и сценарии

## 10.1. Что произойдёт, если пользователь откроет аниме, которого нет в БД, но есть на Shikimori? Проследи весь flow.

1. Пользователь открывает страницу аниме
2. Система проверяет наличие в БД через `src/lib/anime-page-data.ts`
3. Если не найдено - вызывается синхронизация через `src/db/save-material.ts`
4. Запрашивается информация с Shikimori и Kodik API
5. Создаются записи в БД через upsert
6. Отображается страница аниме

## 10.2. Что произойдёт при одновременном просмотре одного аниме в двух вкладках? Как сохранится прогресс?

1. Прогресс сохраняется в БД через `src/app/api/user/progress/route.ts`
2. При одновременном просмотре обе вкладки будут синхронизировать прогресс
3. Последнее изменение будет сохранено (последний активный пользователь)

## 10.3. Что произойдёт, если Kodik API вернёт ошибку во время sync? Есть ли retry? Где это обрабатывается?

1. В `src/lib/sync/kodik-sync.ts` есть обработка ошибок
2. При ошибках система пытается повторить попытку
3. Ошибки логируются в `KodikSyncLog`

## 10.4. Что произойдёт, если сессия пользователя истекла во время просмотра? Потеряется ли прогресс?

Прогресс не потерян, так как:
1. Прогресс сохраняется в БД при каждом изменении
2. Система продолжает работать даже при истекшей сессии
3. При следующем входе пользователь видит последний сохранённый прогресс

## 10.5. Что произойдёт, если мастер watch party отключится? Как передаётся роль?

1. При отключении мастера система автоматически назначает нового мастера
2. Передача роли происходит через WebSocket сообщения
3. Все участники получают уведомление о новом мастере
