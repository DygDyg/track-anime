# Раздел 2 — Инварианты проекта

## 2.1. Какой главный доменный ключ проекта? Запиши равенство из трёх частей.

Главная доменная сущность: `Shikimori anime.id === Kodik shikimori_id === /anime/[shikimoriId]`

## 2.2. Почему браузерный код НЕ может вызывать Shikimori/Kodik API напрямую? Где это проверяется?

Браузерный код не может вызывать API напрямую из-за CORS и безопасности. Проверяется в middleware и API routes через `getSession()`.

## 2.3. Что уникально идентифицирует watch progress пользователя? Почему НЕ по translation?

Уникально идентифицирует `shikimoriId` и `userId`. Не по translation, потому что прогресс один на все озвучки одного аниме.

## 2.4. Как проверяется авторизация в API routes? Назови функции и покажи пример использования в реальном файле.

Проверяется через `getSession()` и `requireAdmin*()` функции.
Пример: `src/app/api/admin/sync/route.ts` - проверяет admin права через `requireAdmin()`

## 2.5. На каком языке user-facing строки? Приведи 3 примера из реального кода.

На русском языке.
Примеры:
- `src/components/Header.tsx` - "Избранное"
- `src/components/KodikPlayer.tsx` - "Плеер"
- `src/components/AnimePageView.tsx` - "Смотреть"

## 2.6. Что такое `KodikMaterial` с точки зрения домена? Чем он отличается от «аниме»?

`KodikMaterial` - это конкретный материал с одной озвучкой. Аниме - это общая сущность, KodikMaterial - конкретная озвучка/перевод.

## 2.7. Где хранится состояние долгих операций (import/sync)? Назови Prisma-модели.

Состояние долгих операций хранится в:
- `KodikSyncSettings` - настройки синхронизации
- `KodikSyncLog` - логи синхронизации

## 2.8. Может ли один `shikimoriId` иметь несколько `KodikMaterial`? Объясни почему и приведи пример.

Да, может. Один аниме может иметь несколько озвучек/переводов (разные KodikMaterial), но один shikimoriId соответствует одному аниме.
