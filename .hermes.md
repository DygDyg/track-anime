## Invariants (never break)

- Browser/client components **never** call Shikimori or Kodik APIs — only server / `src/lib/*` / `src/kodik/*` / `/api/*`
- URL key: `Shikimori anime.id === Kodik shikimori_id === /anime/[shikimoriId]`
- `KodikMaterial` = one anime + **one** translation
- Watch progress unique per `(userId, shikimoriId)`, **not** per translation
- Auth per route: `getSession()` / `requireAdmin*()` — `src/proxy.ts` is legacy redirect only
- Long-running import/sync state lives in Prisma models
- User-facing UI: Russian

## Workflow

1. Study existing implementation first; find a similar pattern; minimal change
2. Multi-topic requests: split by theme (`AI_CONTEXT.md` request routing); **deploy last**
3. Docs-first when user asks to study architecture — no code until model is solid
4. Documentation impact check after behavior/arch changes; update only affected sections; if none → say `Docs: not needed`
5. Verify TypeScript/runtime: `npx tsc --noEmit` and/or `npm run build`. If `npx` broken: `./node_modules/.bin/tsc --noEmit` (Git Bash) or `.\node_modules\.bin\tsc.cmd --noEmit` (cmd)
6. No formal unit-test suite expected — tsc/build, debug scripts under `scripts/`, manual QA

## Deploy (production)

When user asks to deploy / «задеплой» / publish prod:

1. **Site changelog first** — `data/site-changelog.json` via rules in `AI_RULES.md` § Deploy changelog and `.cursor/rules/deploy-changelog.mdc` (same policy):
   - Russian; kinds: `feature` | `improvement` | `change` | `fix`; `audience?: "public" | "admin"` (admin hidden from users, «A» in admin UI)
   - **Daily merge Europe/Moscow**: one entry per day (`id: YYYY-MM-DD`); merge into today's top entry; same-feature → generalize/replace (optional `topic` slug supersedes)
   - Skip if nothing for users or admins; optional public «Небольшие фиксы и исправления»
   - Helper: `upsertDailyChangelogEntry` in `src/lib/site-changelog.ts`
2. Then from repo root: **`npm run deploy:smart`** — do **not** ask webhook/Actions/SSH; script picks channel
3. Report chosen channel + OK/error
4. APK / Windows / RPC binaries are **not** covered by git-pull deploy — separate `deploy:apk` / `deploy:windows` / `deploy:rpc` when needed
